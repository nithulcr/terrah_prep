## 🏗️ Architecture Overview

### Core Principles

1. **ONE Source of Truth**: `testSetsService` is the ONLY service that handles question assignment
2. **NO Runtime Generation**: Questions are assigned ONCE during admin "Generate Test Sets"
3. **NO Random Generation**: No `Math.random()`, no shuffling at runtime
4. **NO Duplicates**: Every question belongs to exactly ONE test
5. **Consistent Counts**: `app_settings.total_questions` is the ONLY question count

### System Flow

```
ADMIN FLOW:
1. Admin uploads questions → questions table
2. Admin clicks "Generate Test Sets"
3. testSetsService.generateTestSetsForBatch() executes:
   - Loads all active questions
   - Shuffles ONCE
   - Assigns sequentially to test sets
   - Stores in test_sets + test_set_questions
   - Validates NO duplicates
4. Questions are now FIXED - never regenerated

USER FLOW:
1. User sees available tests (from test_sets table)
2. User clicks "Start Test X"
3. System loads test_set + test_set_questions (NO generation)
4. User takes test
5. User submits answers
6. System evaluates ONLY those questions
7. Results saved to test_results + user_answers
```

## 🗄️ Database Schema

### Core Tables (DO NOT MODIFY)

```sql
-- Questions uploaded by admin
questions (id, batch_id, category_id, question, options, correct_option, ...)

-- Test sets generated by admin
test_sets (id, batch_id, set_number, name, total_questions, is_active, ...)

-- Junction: which questions belong to which test
test_set_questions (id, test_set_id, question_id, question_order, ...)

-- User test results
test_results (id, user_id, batch_id, test_number, score, total_questions, ...)

-- User answers
user_answers (id, test_result_id, question_id, selected_option, is_correct, ...)

-- Settings
app_settings (setting_key, setting_value, ...)

-- Other tables (unchanged)
batches, categories, plans, subscriptions, user_usage, profiles, bookmarks
```

### Key Relationships

```
questions → test_set_questions → test_sets
                              ↓
                         test_results → user_answers
```

### 1. testSetsService (PRIMARY)

**File**: `src/lib/services/test-sets.service.ts`

**Key Methods**:

```typescript
// ADMIN ONLY - Generate test sets for a batch
async generateTestSetsForBatch(
  supabase: SupabaseClient,

  supabase: SupabaseClient,

async getTestSet(
  supabase: SupabaseClient,
  batchId: number,

// Count available tests (SOURCE OF TRUTH)
async getTestSetCount(
  supabase: SupabaseClient,
  batchId: number

// Get all test sets for a batch
async getTestSetsForBatch(
  supabase: SupabaseClient,
  batchId: number

```

**Shuffle Logic** (Admin Only):
```typescript
// Shuffle ONCE
const questionIds = unassignedQuestions.map(q => q.id);
const shuffledIds = this.shuffleArray(questionIds);

// Assign sequentially
Test 1: shuffledIds.slice(0, questionsPerTest)
Test 2: shuffledIds.slice(questionsPerTest, questionsPerTest * 2)
Test 3: shuffledIds.slice(questionsPerTest * 2, questionsPerTest * 3)
...

// Validate NO duplicates
const uniqueIds = new Set(allAssignedIds);
if (uniqueIds.size !== allAssignedIds.length) {
  throw new Error('Duplicate question IDs detected');
}
```

**File**: `src/lib/services/mock-tests.service.ts`

**Responsibilities**:
- Get available tests for a user

- Calculate unlock status

**Key Methods**:

```typescript

async getAvailableTests(
  supabase: SupabaseClient,

async canAccessTest(
  supabase: SupabaseClient,
  userId: string,
  batchId: number,
  testNumber: number,
```

**NO Question Generation**:

**Responsibilities**:

## 👨‍💼 Admin Flow

### Step 1: Upload Questions

Admin uploads questions via admin panel:
```typescript
INSERT INTO questions (batch_id, category_id, question, option_a, option_b, option_c, option_d, correct_option, ...)
VALUES (1, 1, 'What is...', 'A', 'B', 'C', 'D', 'A', ...)
```

### Step 2: Generate Test Sets

Admin clicks "Generate Test Sets" button:
```typescript
const result = await testSetsService.generateTestSetsForBatch(supabase, batchId);
```

**What Happens**:
1. Loads `settings.total_questions` (e.g., 10)
2. Loads all unassigned questions for batch
3. Shuffles ONCE: `[5, 23, 1, 40, 15, 31, 8, 19, 27, 12, 35, ...]`
4. Creates Test 1 with questions[0-9]: `[5, 23, 1, 40, 15, 31, 8, 19, 27, 12]`
5. Creates Test 2 with questions[10-19]: `[35, ...]`
6. Creates Test 3 with questions[20-29]
7. Creates Test 4 with questions[30-39]
8. Validates NO duplicates
9. Saves to `test_sets` + `test_set_questions`

**Console Output**:

## 🔒 Unlock/Lock Logic

### Free Plan

```
Test 1: Available (if test_sets exists)
Test 2+: Locked (shows "Upgrade Plan" button)
```

**Logic**:
```typescript
if (userPlan === 'free') {
  maxUnlockedTest = 1;
}
```

### Starter Plan

```
Initially:
  Test 1: Available
  Test 2+: Locked

After completing Test 1:
  Test 1: Completed (shows "Retest" + "View Result")
  Test 2: Available
  Test 3+: Locked

After completing Test 2:
  Test 1: Completed
  Test 2: Completed
  Test 3: Available
  Test 4+: Locked
```

**Logic**:
```typescript
if (userPlan === 'starter') {
  const monthlyLimit = plan?.monthly_mock_test_limit || 30;
  maxUnlockedTest = Math.min(highestCompleted + 1, monthlyLimit, totalAvailableTests);
}
```

### Pro/Premium/Elite Plans

```
Same as Starter, but NO monthly limit
```

**Logic**:
```typescript
if (userPlan !== 'free') {
  maxUnlockedTest = highestCompleted + 1;
}
```

### Key Rules

1. ✅ Completed tests remain visible
2. ✅ Next test unlocks ONLY after completing previous
3. ✅ Retest allowed (if user clicks "Retest")
4. ✅ Available tests = COUNT(test_sets)
5. ❌ NOT calculated from remaining questions
